# 採点ナビ — マークシート テンプレート

選択肢式（A〜E）のマークシート解答用紙を、ブラウザ上で設定して印刷・PDF 保存できる静的サイトです。
ビルド不要で、Netlify にそのままデプロイできます。

## 使い方

1. サイトを開く（ローカルなら `index.html` をブラウザで開くだけ）
2. 左のパネルで設定を変更すると、右のプレビューが即座に更新されます
3. 「印刷 / PDF保存」を押す
4. 印刷ダイアログで **用紙サイズ A4 / 向き 縦 / 余白 なし（または最小）** を選ぶ

設定内容はブラウザの localStorage に保存されるので、次に開いたときも同じ設定から始められます。

## 設定できる項目

| 区分 | 項目 | 内容 |
| --- | --- | --- |
| 試験情報 | 試験名 / 科目名 / 実施日 | 用紙上部の見出しに印字 |
| 解答欄 | 問題数 | 5〜200 問（5 問刻み） |
| 解答欄 | 選択肢 | 2択〜5択（既定は 5択 A〜E） |
| 解答欄 | 選択肢の表記 | `A B C D E` / `a b c d e` / `1 2 3 4 5` / `① ② ③ ④ ⑤` |
| 解答欄 | 段組み | 1〜4 段 |
| 解答欄 | マーク内の記号 | マーク（楕円）の中に記号を印字するかどうか |
| 解答欄 | 区切り線 | 5 問ごとに実線を入れて数えやすくする |
| 氏名欄 | クラス / 出席番号 / 氏名 / 得点 | それぞれ表示・非表示を切り替え |
| その他 | 位置合わせマーク | 四隅の黒い基準マーク（読み取り・位置合わせ用） |
| その他 | 正答表 | 採点者用の「正答・配点」記入シートを末尾に追加 |
| その他 | 記入上の注意 | 1 行 1 項目で自由に編集 |

## 用紙のレイアウト

- A4 縦（210mm × 297mm）を 1 ページとして組み、問題数が多い場合は自動で複数ページに分割します
- 1 段あたり最大 34 行。ページ内の問題数は段ごとに均等に割り振られ、段の高さが揃います
- マークは 7mm × 4.4mm の楕円。四隅の基準マークは 6mm 角
- 印刷時は操作パネルが非表示になり、用紙だけが出力されます

## ファイル構成

```
index.html        操作パネルとプレビューの器
Login.html        ログイン画面（/Login で公開）
assets/styles.css 画面表示と印刷（@page A4）のスタイル
assets/app.js     設定の読み書き、ページ割り、用紙の組み立て
assets/login.css  ログイン画面のスタイル
assets/login.js   ログイン画面の入力チェックと送信
netlify.toml      Netlify のデプロイ設定（ビルドなし）
```

外部ライブラリは使っていません。依存パッケージもインストール不要です。

## ログイン画面（`/Login`）

`Login.html` を `/Login`（および `/login`）で公開しています。画面の作りは次のとおりです。

- メールアドレスとパスワードの入力欄、パスワードの表示切り替え
- 送信前の入力チェック（未入力・メールアドレスの形式）と、項目ごとのエラー表示
- 「メールアドレスを次回も表示する」— localStorage に**メールアドレスだけ**を保存します（パスワードは保存しません）
- `?redirect=` が付いていれば、ログイン後にそのパスへ移動します。安全のため、同一サイト内のパス（`/` で始まり `//` で始まらないもの）だけを受け付けます

### 認証サーバーの接続

このサイトはビルドなしの静的サイトなので、**認証機能そのものは持っていません**。
現状の `/Login` は画面と入力チェックまでで、送信すると「認証サーバーが接続されていません」と表示されます。

実際にログインさせるには、`assets/login.js` の先頭にある `AUTH_ENDPOINT` に認証 API のパスを設定してください。

```js
var AUTH_ENDPOINT = '/api/login';
```

API 側に期待している仕様は次のとおりです。

| 項目 | 内容 |
| --- | --- |
| メソッド | `POST`（`Content-Type: application/json`） |
| リクエスト | `{ "email": "...", "password": "..." }` |
| 成功 | `200` を返し、セッションは `Set-Cookie` で発行する |
| 認証失敗 | `401`（`400` も同じ扱い） |
| 回数制限 | `429` |

パスワードの照合、セッションの発行、試行回数の制限はすべてサーバー側の責任です。
クライアント側だけでログインを成立させることはできません。

```sh
npx http-server -p 8080 .

```
